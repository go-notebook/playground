# R cells, checked but not run yet

A cell written in an `r` fence is **parsed and checked** with [go-embedded-r](https://go-embedded-r.github.io/)'s parser, and it is **not run**: go-embedded-r has no evaluator yet (its milestones M2 and M3). Until that lands, an R cell is checked, not run. There is no external `R` behind it. The badge on the cell says so: *R · not runnable yet*.

The parser gives the same trees as R 4.6.2 on all of R's own sources, so the notebook knows what each R cell assigns and what it reads, and which Go cells depend on it. Go draws the size; the R cell reads `n` and assigns `xs` and `total`.

```go
n := 10
```

The R cell below is well formed, so it is not an error. It does not run either: its output says why, and no number comes back. `square` is an R function: it stays R's, and only the variables cross to the other languages.

```r
square <- function(v) v^2
xs <- square(seq_len(n))
total <- sum(xs)
```

This Go cell reads `total`, which the R cell assigns. The name analysis sees that, so the cell is **blocked**: it waits for the R cell, and says so, instead of failing on a name that never arrives.

```go
m := total + 1
```

A cell that does not read anything from R is not held back. It runs as usual, whatever the R cells above it do:

```go
n * 2
```

A mistake in an R cell is caught at the right line, before anything runs, in R's own words, and the cells that do not read it still run. This notebook would stop being published if one of its cells had one, so here is one, quoted. With a cell that reads

> y <- 2
> x <- y y

the page shows `line 2:8: syntax error: unexpected symbol`, at line 2, column 8, where R finds a second name with no operator between them. Try it: add an R cell with `x <- y y` and run the notebook.

Some R cannot be analysed from its text alone: `x <<- 1`, `assign(name, v)` with a computed name, `eval(parse(...))`, `attach`, `library`. Such a cell is **dynamic**: the notebook makes it depend on every cell above it, and every later cell that reads a name depend on it.

When go-embedded-r's evaluator lands, these cells will run and the blocked cell will compute `total + 1`. Follow the progress at [go-embedded-r.github.io](https://go-embedded-r.github.io/).
